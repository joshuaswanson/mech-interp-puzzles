How a tiny transformer counts unique letters

A 2-layer attention-only transformer reads ten letters and says how many different ones there are. Every number on this page is computed live from the real model's weights. The input bar stays at the top while you scroll, so you can change the letters at any point and watch every figure update.

model's answer

Type ten letters from a to j in the bar. The model sees twelve tokens. Position 0 is a fixed start token $\mathrm{BOS}$, positions 1 to 10 are the letters, and position 11 is a fixed token $\mathrm{ANS}$ that means "answer now". The answer is read off at position 11. Each token starts as a fixed 32-number vector (its embedding). Two layers of four attention heads each add to those vectors. Then ten answer vectors score the final vector at position 11, and the highest score wins.

Attention matrix

Pick a layer and a head. Queries run along the top, keys down the left, and each column is one query position's attention weights, which add up to 1. Darker is larger. Empty cells are masked (a key that comes after its query). Click a cell to highlight its column; the cards in the counter section jump here.

With layer 0 selected, the layer 0 key rankings appear under the matrix. In layer 0 a score depends only on the two tokens, so each head ranks the key letters in one fixed order for ordinary queries and in a different fixed order for the $\mathrm{ANS}$ query. The rankings are read straight from the score tables and do not depend on the input. With layer 0 selected, every column of the matrix is that head attending to the highest-ranked letter available in its prefix. That makes each layer-0 head a detector for its top-ranked letter: whether it found that letter is one bit, stored in the vector at that position. The four heads look for $\mathtt{a}$, $\mathtt{h}$, $\mathtt{d}$, $\mathtt{g}$ at ordinary positions and for $\mathtt{i}$, $\mathtt{j}$, $\mathtt{c}$, $\mathtt{e}$ at $\mathrm{ANS}$, eight bits from four heads. The last two letters get special treatment: a $\mathtt{b}$ query reverses every ranking and an $\mathtt{f}$ query has almost none, so the vectors at $\mathtt{b}$ and $\mathtt{f}$ positions look unlike any other and layer 1 can find them directly.

Layer 1: four heads that add up the bits

By now the vectors are no longer just tokens. After layer 0, the vector at position $j$ is its token's embedding plus what the four layer-0 heads wrote there, and what they wrote is which letter each of them found. Those four letters are listed per position in the walkthrough table below. At $\mathrm{ANS}$ it is the $\mathrm{ANS}$ embedding plus the four letters found with the $\mathrm{ANS}$ rankings. Layer 1's queries, keys and values are all computed from these stamped vectors. That is the whole trick: layer 0 stamps every position with "which of $\mathtt{a}$, $\mathtt{h}$, $\mathtt{d}$, $\mathtt{g}$ have appeared so far", and layer 1 reads the stamps.

Each layer-1 head, at the $\mathrm{ANS}$ position, adds one unit along a fixed "count direction" for every letter of its group that is present: head 0 for $\mathtt{b}$, head 1 for $\mathtt{f}$, head 2 for $\mathtt{a}$ $\mathtt{d}$ $\mathtt{g}$ $\mathtt{h}$, head 3 for $\mathtt{c}$ $\mathtt{e}$ $\mathtt{i}$ $\mathtt{j}$. Three of them put the count in what they copy (the value at the position they attend to). One puts it in how much attention stays on $\mathrm{BOS}$. The walkthrough below shows the arithmetic for one head at a time.

To read the number a head adds, measure its output by its count slope, the amount it pushes the answer toward larger counts (the slope of its ten answer logits against the answer index). Subtract the head's baseline (its slope when none of its letters are present) and divide by the size of one unit.

The readout: turning "count" into an answer

After layer 1, the vector at $\mathrm{ANS}$ is roughly $U$ times the count direction plus a fixed offset, where $U$ is the number of different letters. Each answer token $c$ takes a dot product with it. The answer tokens are arranged so that this dot product is a downward parabola in $c$ whose peak sits at $c \approx U$:

$$\ell_c \approx 32.5\, U c - 16.2\, c^2 - 9.9\, c + \text{const}.$$

Answer token $\#c$ "wants" the count to be near $c$, and the quadratic penalty makes exactly one of them win.

The whole thing in one breath

The answer is a sum of ten yes/no bits, one per letter. Layer 0 computes eight of them with four detector heads, each used twice (once at ordinary positions, once at $\mathrm{ANS}$), and marks the other two letters so they can be found by attention. Layer 1 adds the bits along one direction with four heads that split the alphabet 1 + 1 + 4 + 4. The answer tokens read the total with a parabola that peaks at the right count.

The accompanying notebook shows the evidence for each step, including patching experiments that remove one detector at a time and watch the count drop by exactly one.
